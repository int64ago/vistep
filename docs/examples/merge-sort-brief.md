# Merge sort — author brief

Misconception: divide-and-conquer is just splitting, or a merge can safely compare heads of any two lists. Prerequisite: ordered sequences and a persistent item ID. Distinction: other computing scenes move packets or build codes; here the causal object is one sorted run becoming a longer sorted run.

Art direction: two quiet paper streams, pale blue and sage, feeding one output. The current head and just-output identity carry emphasis; no bar-height spectacle or dashboard. A continuous input ribbon separates into singleton runs before the first merge. On phone, two compact vertical source columns (two visible items plus an explicit remaining count) and a four-column output retain 16px IDs and visible equal-key ordering. Desktop gives the output a single eight-item row. Input identity is reused through every pass.

| Claim                                                      | Source                                                                                                                           | Conditions                                                      |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| Sorted runs can merge by comparing only their heads        | [Princeton, Mergesort](https://algs4.cs.princeton.edu/22mergesort/)                                                              | Each input run is already ordered                               |
| Stable equality handling preserves original relative order | [Princeton Merge API](https://algs4.cs.princeton.edu/code/javadoc/edu/princeton/cs/algs4/Merge.html) plus explicit left-tie rule | No reverse-copy unstable variant                                |
| Passes of length 1,2,4 sort this eight-item input          | Bottom-up trace generated by the model                                                                                           | Auxiliary output storage; history is additional teaching memory |

Independent benchmark: native numeric+origin reference sorting over 65 lengths×8 seeded inputs; item-ID conservation in every local frame; hand final values 1,2,3,3,5,6,7,8 with 3#2 before 3#4. Final 4+4 merge makes seven head comparisons. Counterexample: 1,4,2 merged blindly with 3,5 yields 1,3,4,2,5; the public interface rejects it. Empty runs, odd lengths and invalid/duplicate identities are checked.

Six shots: mixed ribbon; singleton sorted runs; pairwise first pass; equal 3s and left-tie stability; full final merge; unsorted-run counterexample. Planned 133 seconds, with no repeated loop. Scripts name head, run and immutable number rather than a responsive screen direction.

Category `computing`, age 10; related `huffman`, `lz77`, `dijkstra`. Suggested later crosslinks with quicksort to compare stable merging versus unstable partitioning. Author model/syntax checks only.
