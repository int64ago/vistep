# eSIM：跟住同一份受保护的 profile

[English](../../examples/esim-brief.md)

## 因果问题

手机没有卡槽，用户身份存在哪里？扫码怎样把新订阅送进去？跟住一份旅行 profile，从下载线索、双向认证与绑定封包，直到同一个实体 eUICC。转折是把同一份绑定封包复制给另一颗芯片，安装被拒绝。完整安装与单独启用必须呈现为两个步骤。

采用消费类 GSMA RSP 的激活码路径与设备内 LPA，不混入无人值守 IoT 的 SGP.32 架构。建议 12 岁起观看：主片需要区分线索、受保护凭据与认证应答，不要求读者先掌握标准细节。

## 原创表现与手机构图

原创工程切面揭示主板、屏蔽区、连线、电池与独立 eUICC。它是概念性的焊接实现，不复刻特定手机，不按半导体封装真实尺寸绘制。封面与主画面使用同一组手机比例和芯片位置。芯片局部图放大实体对象，锁表示保护边界，不显示密钥内容。

每一步按现象改变表达：实体切面、激活线索字段、双向认证时序、经过 LPA 的同一个封包、隔离存储、移动网络挑战应答。桌面传输横向，手机改成纵向，保留服务器、LPA 与芯片三个因果角色；其他章节把当前证据放满可用宽度。SVG viewBox 宽度跟随实际舞台测量，标签以 16 CSS px 绘制；舞台高度 342 px。包含最长双语字幕与控制条的完整播放器仍需集成人员实看。

激活码图案故意不可扫描，示意地址使用保留域 `.invalid`。不展示真实 token、EID、IMSI、ICCID 或网络密钥。主画面与静态路径共用轻量 SVG，无运行时 WebGL 或 Worker 依赖；这不绕过网站的启动能力门槛。

## 计划共享窗口

六章各 24 秒，计划 144 秒；正式时长以合成录音后的规范时间线为准。测量时长、独立转写、原生试听与完整观看分别记录。

| 窗口       | 新的可见因果步骤                                                |
| ---------- | --------------------------------------------------------------- |
| 0–24 秒    | 手机外壳揭示主板与 eUICC，相连局部图指出同一颗芯片。            |
| 24–48 秒   | 服务器地址与订阅参考号分开，LPA 找到准备好的 profile。          |
| 48–72 秒   | 先确认服务器，再确认芯片；双方通过才允许绑定。                  |
| 72–96 秒   | BPP 经 LPA 以八段示意进入 A；复制给 B 的同一份绑定封包被拒绝。  |
| 96–120 秒  | 完整安装生成停用旅行 profile；之后单独启用，日常 profile 保留。 |
| 120–144 秒 | 启用 profile 用芯片中的 K 计算应答；换线路改变身份并重新认证。  |

全部导演状态来自共享章节和进度，没有独立持续计时器。直接跳转立即重建前置步骤、收到的分段、存储 profile、启用身份及网络认证结果。复制给另一芯片的拒绝比较与原来的成功交易分开。

## 模型与边界

`src/models/esim.ts` 强制查找、服务器认证、芯片认证、绑定、完整接收、安装、启用的依赖。网络认证是后续操作。服务器不可信、收件芯片不同、封包被改动或下载前无网络，均不替换原 profile。接收段数单调增加，安装要求收齐八个教学段，不可变更新保留输入状态。单端口换线路清除网络认证结果。

这是协议状态机，没有实现真实签名、ECDH、加解密、APDU 编码或运营商服务。通过/失败代表标准中相应校验结果。八格不是实际文件大小、速率或 APDU 数。故障选项重建同一笔可复现交易，不是截获真实网络包；断网只模拟下载前缺少连接，不处理途中重试。

本图允许一份启用 profile，现代双 eSIM 或多启用 profile 取决于端口、基带、系统、设备与运营商支持。存储容量和同时启用数不能混同。其他消费类发现与转移路径不在本片范围。
