[English](../../examples/hash-brief.md)

跟住 `abc` 中 `a` 的最低位，走完真实 SHA-256。开头追踪字节/消息字的明确位置，后面改为严格对照：同一输入仅翻转一位，完整重算两次。混合运算后观察的是计算影响，不宣称某个输出格就是原来的那一位在机器里移动。

## 构图与八章

冷色纸面上的文字与细线谱：字母、字节短线、填充带、四项消息扩展、两条压缩支路、八个紧凑状态字与明确的加回弧线。金色表示被跟踪输入或实测异或差异；曲线是算法依赖，不是物理连线。没有机柜、装饰性二维码矩阵或虚构硬件耗时。

| 开始   | 章节     | 可见因果变化                                                 |
| ------ | -------- | ------------------------------------------------------------ |
| 0 秒   | 字节     | UTF-8 为 61 62 63；a 的 b0 成为大端 W[0] 的位 24。           |
| 22 秒  | 填充     | 依次加入一位 1、零、原始 64 位长度字段，组成 512 位块。      |
| 44 秒  | 消息扩展 | 用真实四项输入分别算 W[16]、W[17]、W[18]、W[63]。            |
| 66 秒  | 一轮     | 展开 T1、T2，再生成 a′、e′，显示真实首轮数值和其余字的传递。 |
| 88 秒  | 六十四轮 | 八个工作字逐轮更新，同时显示当前 W 和 K。                    |
| 110 秒 | 加回     | 最后一轮的八个工作字，逐项加回块输入状态。                   |
| 132 秒 | 双块     | NIST 56 字节示例：前块完整链值进入后块，再显示最终摘要。     |
| 154 秒 | 一位对照 | 61 62 63 与 60 62 63 在相同阶段比较；最终差异 112/256 位。   |

八章各 22 秒，**草稿 176 秒**；语音起点为章节起点加 0.45 秒。中文和英文分别创作，中文每章 89–100 字符，英文每章 48–55 个空格分隔词。父任务测量声音并决定最终录音时间轴。

交接时**冻结双语脚本、字幕、标题、章节顺序/数量和草稿时间点**。UTF-8 `JSON.stringify(packet.narration)` 的 SHA-256 为 `5ac6c4903062f7db806d74aab05049f7bd692e1f562291641bd62ae20f708253`。冻结后只修改了无障碍标签、文字对比度与封面。packet 是临时交接数据，父任务写入中央真源后接管。

## 模型与边界

独立 TypeScript 模型按 FIPS 180-4 执行：界面边界显式 UTF-8、大端 64 位原始长度、字节对齐填充、512 位分块、16→64 消息扩展、全部 64 个固定 K、八个初始字、每块 64 轮、模 2³² 加法、feed-forward 加回、按大端顺序拼接摘要。小 σ 包含右移，大 Σ 只有循环右旋；Ch、Maj 逐位运算，新一轮完全从旧状态生成。

默认摘要 `ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad`。仅翻转字节索引 0、位 0 后，摘要为 `89f900390e14d37c405c75244fb086aa35b54c0fb6ec3638c1c21451d4743d11`。W[0]、W[16] 的异或差为 0x01000000，首轮 T1 改变而 T2 不变。状态差异序列从 `0, 3, 23, 48, 80, 109` 开始，保留真实回落；没有强制单调上升或终点 128。

详细轨迹限制 1024 UTF-8 字节，最多 17 个填充后块。空消息有效并禁用翻转。不完整 Unicode 代理项会拒绝；不做规范化或静默替换。对照翻转原始字节，其结果未必还是合法 UTF-8。另有不保留逐轮轨迹的摘要路径，已验证百万字节。模型不实现流式接口，也不处理标准允许的非整字节位串。

固定长度必然允许碰撞存在，但没有演示寻找碰撞。哈希与编码、加密区分清楚，不提供可逆恢复，也不声称抗碰撞、抗原像、密码强度或安全认证。雪崩画面是两次计算的实测，不是安全证明或每次恰好改变一半的保证。

## 手机、无障碍与生命周期

手机逐章选择重点，去掉重复标题。加回与双块章保留字值，移除次要位纹。最后一章只展开前两个数值对，并紧凑保留八组 XOR 短线，完整比较 256 位，避免上下堆叠大矩阵。每个字仍有包含两边真实数值的翻译无障碍分组名称。正文及标签不低于 16px。

探索包含明确命名的文字、字节、位、块控件；range 同时有显式标签关联、翻译 `aria-label` 和语义 `aria-valuetext`。前进/后退按钮不依赖拖动。完整重置恢复 `abc`、字节 0、位 0、翻转开启、块 0、步骤 65，并关闭详情。无效输入移除旧结果；完整摘要和 Σ/Ch/Maj 数值按需展开。

`hashShot(chapter, progress)` 选择教学状态；`hashAt(run, block, step)` 选择数学状态：0 为块输入，1–64 为轮结束，65 为加回。没有私有时钟、随机状态或逐帧累积。逐轮轨迹来自同一字节串的完整计算，与播放历史无关。共享 Showcase 负责后台/离屏暂停与声音；只在播放时过渡刻度颜色，减少动态模式禁用过渡。本篇不分配 WebGL、Worker、音频对象、计时器或对象 URL，SVG/HTML 就是二维默认路径，没有透视相机需要拟合。

## 精确针对性证据

- `pnpm exec vitest run src/models/hash.test.ts`：Vitest 5.0.0 / Node 24.19.0，**10 项通过**。涵盖两个 NIST 摘要、五个公开完整轮状态、公开第一块链值、0–129 字节长度、七种 Unicode 输入、百万 a、填充边界 0/55/56/63/64/119/120/1024、独立 BigInt 右旋与模运算、八种单比特 Ch/Maj 真值组合、abc 的全部 24 种单比特扰动、真实汉明距离、多块传播、直接/逆向定位、错误输入与不可变性。
- 测试中的 WebCrypto SHA-256 独立核对共 **162 个输入**：130 长度 + 7 Unicode + 1 百万字节 + 24 扰动，全部一致。
- 独立 Node `createHash('sha256')` 核对 **1,031 个输入**：0–1024 每种字节长度及六个 Unicode/标准示例，全部一致。Node 24.19.0、OpenSSL 3.5.7。WebCrypto 与 Node crypto 均独立于本实现，但内部可能共享 OpenSSL，不声称它们是两个独立设计的密码核心。
- 独立审看目录 `/tmp/vistep-hash-review/` 使用自己的依赖和复制源码，无共享 `node_modules` 符号链接或配置改动。静态 fixture 使用实际共享样式与 FilmContext，仅在内存注入 packet 翻译，不包含共享播放器或音频。
