# CPU、GPU、NPU — 制作说明

[English](../../examples/cpu-gpu-npu-brief.md) · [制作指南](../creating-a-scene.md)

## 现象与方向

为什么几种处理器能算出同样的答案，却安排工作的方法不同？跟住固定身份的 Y11，把同一份 `ReLU(XW)` 交给三种教学调度。转折不靠速度排名：GPU 让不同数据身份共享指令，NPU 示例让相邻乘加单元共享经过的数据。最后逐项核对十六个输出。

采用 HTML 数字矩阵与连接 SVG 总线，不把芯片外壳当作解释。暖色权重、蓝绿色输入与柔和纸面有稳定的语义。CPU 程序控制、GPU 通道和 NPU 阵列各自构图，避免统一套板。

## 模型与资料

- [NVIDIA CUDA 编程模型](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html)：异构任务、SIMT 掩码、矩阵专用编程和内存。四条教学通道不是 NVIDIA 的 32 线程 warp；ReLU 刻意拆成路径展示掩码，真实编译可能无分支。
- [Google 第一代 TPU 论文](https://research.google/pubs/in-datacenter-performance-analysis-of-a-tensor-processing-unit/)：矩阵加速与局部存储的一手实际案例。4×4 输出驻留阵列不是该 TPU 的复刻，也不代表全部 NPU。
- [Intel NPU 技术资料](https://edc.intel.com/content/www/us/en/design/products/platforms/details/arrow-lake-s/core-ultra-200s-series-processors-datasheet-volume-1-of-2/intel-neural-processing-unit-intel-npu/)：专用乘加、近计算存储与调度。

独立模型负责输入、权重、可复现轨迹与章节导演。CPU 每个输出四次乘加再判断；GPU 每组四输出共同乘加，再执行实际非空的保留／置零掩码；阵列让两流在 `i + j + k` 拍相遇，部分和留在对应单元，最后执行激活。三种安排都做完整 64 次乘加，权重冻结。未模拟真实时钟、能耗、量化、缓存和温度。

## 分镜与手机构图

计划 7 章、170 秒：0 秒同一道题，24 秒 CPU 控制，48 秒 GPU 并行，72 秒分支掩码，96 秒 NPU 阵列，122 秒数据搬运与协作，146 秒逐项核对。实际双语录音需要集成人测量，计划窗口不是录音证据。

桌面用两输入矩阵、四积带、并行通道与阵列分别解释当前因果。手机保留当前因果视图：CPU 省去重复工序带；GPU 共同指令独占一行；NPU 阵列重新构图为 272 px，单元保持 16 px 身份和可读部分和，把详细乘积放到具名观察条；协作图分两行；最终三矩阵仍显示真实十六个数。没有把整块桌面 SVG 缩小。

自动推进只使用 Showcase 统一时钟与章节进度，暂停时关闭过渡，直接跳章读取确定性轨迹。探索使用逐步推进和输入切换，没有独立动画计时器；全零、输入取负会改变真实计算并回到零步。单元点选改变教学焦点，并显示精确输入、权重和累加式。正文／图示文字至少 16 CSS px，操作目标至少 44 px。

## 作者自审与交接

可复现关键停帧：第 1 章进度 0.40 的 Y11=2；第 3 章 0.50 只有 Y13 被掩蔽，0.90 其余三条通道被掩蔽；第 4 章约 0.45 出现斜波前，1.00 全部输出执行 ReLU。阵列单元宽度 18%、间距 24%，中心与模型／SVG 共用坐标，末端单元和选中轮廓均在表面内。

模型测试逐项检查独立乘法答案、64 次乘加的身份、正负零掩码、错开流到达时刻、非法输入和不可变回放；表现测试覆盖直接跳到掩码、全部七种视图以及改成全零后换调度的真实结果。边界输入还包括取负、单位权重与小数。

这些是作者自审，不能代替独立视觉验收。桌面／390／320 px 双语完整播放器、连续观看、键盘触控、减少动态、封面各入口、双语原生配音与真机性能仍需集成人分别记录。本篇不自行创建 Worker、WebGL 或音频资源；公共播放器的能力门与语音失败路径仍须独立检查。packet 只供交接，完成正式登记后应移除。
