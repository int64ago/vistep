<h2 id="understand">没有卡槽，SIM 到哪儿去了？</h2>

eSIM 省掉了换卡时的拔插动作，却没有省掉保存身份的安全硬件。这里追踪的是一部消费类手机里的 **eUICC**：能安全保存、安装和管理运营商 profile 的硬件与软件组件。画面采用焊接在主板上的独立芯片示例；标准也允许可移除或集成的实现。Profile 则是一份运营商的数据与应用，包括网络接入应用 USIM、用户身份 IMSI 和认证凭据。这两个对象不能混为一谈。[GSMA SGP.21 v2.6](https://www.gsma.com/solutions-and-impact/technologies/esim/wp-content/uploads/2024/09/SGP.21-v2.6.pdf) 区分了它们。

扫描运营商的激活码，只是给手机的 **LPA（本地 profile 助手）**提供下载线索：去哪个 SM-DP+ 服务器，领取哪份订阅。它并没有把长期网络密钥 K 印在二维码里。手机还需要已有的互联网连接，例如 Wi-Fi，才能走完这条下载路径；激活码本身不会制造信号。

接下来，SM-DP+ 与 eUICC 通过证书和新鲜的认证消息确认对方。服务器把 profile 制成受保护、并与目标 eUICC 密码绑定的 **BPP（绑定 profile 封包）**。LPA 下载并分段搬运它；封包到达芯片后才经过受保护的处理与安装。把同一份绑定封包交给别的芯片，不能让它变成第二张可用 SIM。[SGP.22 v2.2.2](https://www.gsma.com/solutions-and-impact/technologies/esim/wp-content/uploads/2020/06/SGP.22-v2.2.2.pdf) 详细规定了协议与封包。

**安装完成，不等于线路已经启用。** 下载的 profile 首先安装为停用状态。用户再确认启用，手机的基带才使用被选中的 profile 进行网络注册与认证。网络发来随机挑战，芯片使用其中的长期密钥计算应答；认证时密钥不作为无线消息发送。eSIM 改变了订阅进入手机的方式，基带、天线与移动网络仍承担通信。

<h2 id="try">只改一处，看看停在哪里</h2>

- 选“安装与启用”，拖动步骤进度：完整安装以后，旅行线路仍是停用状态；再推进到启用，日常线路仍被保存在芯片中。
- 选“服务器证书不可信”：流程停在身份验证，不能继续绑定与安装。
- 选“把封包给另一芯片”或“封包被改动”：已经存在的日常线路保留，新旅行 profile 不会部分启用。
- 选“下载前断开互联网”：下载线索并不能替代网络连接。这个输入只模拟开始下载时缺少连接，不模拟传输中重试策略。
- 正常流程来到“再向网络认证”，切换日常与旅行线路。变的是选用的 profile 与身份；不是换天线。

<h2 id="deeper">身份下载与网络认证是两件事</h2>

<details>
<summary>eUICC、IMSI、ICCID 与 EID 有什么区别？</summary>

EID 标识 eUICC，ICCID 标识 profile，IMSI 标识运营商网络中的订阅。它们承担不同工作，不能用手机号码替代所有编号。画面只使用“A”“日常”“旅行”等符号，不展示真实激活 token、订阅编号或密钥。锁形状表示保护边界，并不是密钥的内容。

消费类远程配置使用证书、公钥密码与安全封包。完成安装后的移动网络认证，使用 profile 中的网络凭据与相应的 3GPP 认证协议；下载服务器的证书不是网络认证密钥 K。已有[国际漫游专题](/explore/mobile-roaming/)进一步展开挑战应答和归属网络的作用。

</details>

<details>
<summary>只能启用一份 profile 吗？</summary>

本图选择传统单启用端口的教学模型：可以存多份，当前只选一份。它并不是所有现代手机的硬性限制。支持双 eSIM 或多启用 profile 的设备可结合多个端口、基带和系统能力，同时使用更多线路。例如 [Apple 的双 SIM 说明](https://support.apple.com/en-euro/guide/iphone/iph9c5776d3c/ios)列出了支持两份 eSIM 的机型。实际数量、运营商政策与区域支持以设备和服务条件为准；存储容量与同时启用数量也不是同一个指标。

</details>

<details>
<summary>这个模型没有做什么？</summary>

这是消费类 GSMA RSP 的激活码路径；未展开 SM-DS 发现、自动转移、运营商业务开通、确认码、恢复与其他可选路径，也不把它当作 SGP.32 的无人值守 IoT 流程。八个传输格是教学分段，不是实际 APDU 数量、文件大小或下载速度。

独立状态机检查认证、绑定、完整接收、安装和启用的依赖，并保留失败时原线路。证书与完整性校验以通过/失败状态表达，没有执行真实签名、密钥协商、解密或运营商服务。手机切面与芯片位置为原创工程示意，不复刻某一机型，也不按真实封装比例放大。

</details>
